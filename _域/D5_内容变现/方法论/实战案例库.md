## ⭐ 案例 1：定妆照不合格 → 后续全崩

| 项 | 内容 |
|---|---|
| **现象** | 用「女主捂嘴笑」的图当锚点 → 后续所有镜头女主脸周围有**莫名其妙的阴影**，怎么调都调不掉 |
| **原因** | 定妆照带有**明显角度、夸张表情、复杂光影** → AI 提取的特征"不稳定" |
| **修复** | 换成**正脸无遮挡、光线干净的三视图** → 问题立刻消失 |
| **教训** | **锚点图必须：正脸 + 无遮挡 + 干净光线** |

## ⭐ 案例 2：提示词与锚点冲突 → 角色崩掉

| 项 | 内容 |
|---|---|
| **现象** | 锚点写「黑色齐刘海」，某镜头提示词写「金色长发」→ **认知冲突，角色彻底崩** |
| **修复** | **单镜头提示词尽量不要出现外貌描述词**（除非剧情需要换装） |
| **教训** | 外貌**只在锚点定义**，镜头里不重复描述 |

**⚠️ 这修正了我之前的做法！**
```
我的剧本：每镜都写"陈默：26岁…短黑发…" → 可能与锚点冲突
正确做法：锚点定义一次，镜头里不写外貌
```

## ⭐ 案例 3：角色库标准（OSCHINA 数据）

| 项 | 标准 |
|---|---|
| **基准锚点图** | **全景 + 正脸 + 45度侧脸 + 表情（喜/怒/哀）= 6-8 张** |
| **单图分辨率** | 建议 **1024×1024** |
| **提示词锚定** | 用固定身份标识符（如 `[char_a]`） |
| **负向提示词** | `bad anatomy, extra limbs, mutated face, deformed eyes:1.4` |

## ⭐ 案例 4：风格锚定（SegmentFault）

| 项 | 内容 |
|---|---|
| **做法** | 项目创建时**选定风格 → 全局锚定** |
| **效果** | 所有分镜在**笔触/饱和度/色彩/明暗**上高度统一 |
| **教训** | **风格要一次性锁定，不能每镜各写** |

## ⭐ 案例 6：自动化流水线（CSDN）

| 项 | 做法 |
|---|---|
| **批量生成** | 分镜表当数据集 → ComfyUI 模板化 → 一次批量出候选图 |
| **自动切分** | API 脚本切配音、批量转字幕 |
| **模板化** | 剪辑工程模板（固定 BGM/字幕/转场）→ 快速套壳 |
| **原则** | **人只做筛选和决策，重复劳动交给工具** |

## ⭐ 案例 7：LLM 分镜稿规范（45天320集实战）

| 项 | 做法 |
|---|---|
| **枚举约束** | 景别必须从枚举里选（近景/过肩/大全景） |
| **引用而非描述** | 场景/角色用 **ref ID 引用**（图库才能复用） |
| **时长用浮点秒** | 不用"长/短"模糊词（便于对齐音频） |
| **finetune** | 800集标注数据 → JSON 合规率 **99.4%**（vs GPT-4 直出 76%） |
