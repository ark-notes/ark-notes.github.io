# 能力移植框架（通用方法）⭐

> 建立：2026-10-05
> 来源：用户洞察 —— "你不会找会的，你是智能体"
> 核心：不擅长的领域，用【掘取+考试+打包】把专家能力搬进来

---

## 一、核心思想

```
我（MasterD）不是"自己变强"
而是：【把专家的能力搬进来，打包成模块，我加载】
        ↓
= 我是智能体 → 该做"整合/移植/执行"
  不是"从零自己摸索"（那是低效的）
```

---

## 二、⭐ 能力移植框架（4步闭环）

### 第1步：定位短板
```
· 我哪块弱？（视觉/某领域/某技能）
· 明确：缺"知识"还是缺"能力"还是缺"方法"
```

### 第2步：找专家 + 掘取
```
· 找"会的人"（其他AI/专家/资料）
· 用【掘取问法】让它输出：
  - 知识（事实/规则）
  - 方法（流程/判据/标准）
  - 清单（checklist）
  - 决策逻辑（怎么选/排查）
  - 隐藏规则（它没主动说的）
```

### 第3步：对标学习 + 考试验收
```
· 让专家【出题】
· 我【作答】
· 专家【批改】：打分 + 指出错处 + 给改进
· 反复直到"考过"
        ↓
= 用"考试"验证"真学会"（不是"看过"）
```

### 第4步：打包成模块
```
· 把知识/方法/标准/清单 整理成文件
· 存到对应领域目录
· 4处备份（防丢）
· 我"加载"后即可调用
```

---

## 三、⭐ 掘取问法模板（榨干专家）

```
【知识层】
"把XX领域的全部知识，系统输出成手册，
 分N部分，尽可能具体"

【方法层】
"你分析/处理XX时，具体什么步骤？
 什么维度？判据是什么？有无checklist？"

【主动性/决策层】
"你什么情况直接做、什么情况问？
 你的决策规则/优先级是什么？"

【暗知识层】
"还有什么没讲的？行业不愿说的？新手不该早知道的？
 你自己不确定的是什么？"

【验收层】
"出10-15道考题（含情景题），我先答，你再批改。"
```

## 四、⭐ 能移植 vs 不能移植

| 能移植（打包成模块）| 不能移植（用替代方案）|
|---|---|
| 知识（事实/规则）| 别人的算力/感知（视觉/语音）|
| 方法（流程/判据/标准）| 别人的实时计算能力 |
| 清单（checklist）| 别人的模型权重 |
| 决策逻辑（选/排查）| — |
| 模板/公式 | — |

**不能移植的 → 替代方案：**
```
· 用【工具】补（如 OCR / 人脸分析库）
· 用【方法】补（如对照判据，不靠"感觉"）
· 用【人】补（用户的眼睛 = 最终标准）
```
