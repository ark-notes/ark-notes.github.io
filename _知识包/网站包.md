# 网站包 · 网站制作完整方法论

> ⭐ 可直接喂给其他 AI，作为「做网站」的完整工作手册
> 整理自 MasterD 网站实践 + 知识库 + 审查经验
> 建立：2026-10-04

---

# 第一部分 · 技术选型（先定方向）

## 1.1 选型的铁律

| 网站类型 | 用什么 | 为什么 |
|---|---|---|
| **公司官网/个人主页/展示页/活动页/作品集** | **纯 HTML/CSS/JS** | 零 build 失败风险 ✅ |
| 需要搜索/筛选/购物车/表单/实时数据 | React/Vite | 交互功能才需要 |

**⚠️ 默认用纯 HTML** —— 除非用户明确要交互功能。

## 1.2 用了 React/Vite 的硬要求

```
必须在 vite.config 设 base: './'
否则公开 URL 白页
```

# 第二部分 · 端口与服务器

## 2.1 端口规则

```
✅ 范围：10000-65535
✅ 简单网站默认：10000
❌ 禁止：5173、4173（Vite 端口，会白页）
❌ 禁止：1024、3000、8080（系统/冲突）
```

## 2.2 服务器管理铁律

| # | 规则 |
|---|---|
| **1** | 启动新服务器前**必须**检查已有进程，kill 同端口/死进程 |
| **2** | **禁止**同端口多服务器 |
| **3** | **禁止** `&`、`nohup`、`disown` 启动 |
| **4** | 只用 process 工具管理长任务 |

# 第三部分 · 文件组织

## 3.1 目录规则

```
所有网站文件（HTML/CSS/JS/图片）必须在同一个目录树
index.html / style.css / script.js 必须在同一目录或正确相对路径
```

**❌ 错误：** HTML 在 public/，CSS 在父目录
**✅ 正确：** 全部在同一目录

## 3.2 静态服务器

```
--directory 必须指向包含 index.html 的完整站点目录
```

# 第四部分 · 视觉规则

## 4.1 硬性要求

| # | 规则 |
|---|---|
| **1** | ❌ **禁止 emoji 当 icon** → 用 iconify/Phosphor/Tabler |
| **2** | ✅ **必须有真实图片**（image_search 或 image_generate） |
| **3** | 图片放 public/ 或框架公开文件夹（不相对路径） |

## 4.2 品牌一致性

**ARK 相关网站**：用 workspace 根目录的 `arkie-mascot.png` + `image_edit` 生成品牌图。

# 第五部分 · 开发流程（分步验证）

## 5.1 核心原则：逐步验证

```
写代码 → 验证 → build → 验证 → 启动服务器 → 验证
→ publish → 验证
```

**⚠️ 不要在一个 turn 内做完所有步骤。**

## 5.2 构建与发布

| # | 规则 |
|---|---|
| **1** | ❌ 禁止把 dev server 当交付 |
| **2** | ✅ 必须 build 后用静态服务器提供 dist/ |
| **3** | publish 前：`ss -ltnp` 确认 listener |
| **4** | publish 前：`curl localhost:$PORT` 确认返回 HTML |
| **5** | publish 后：`curl $PUBLIC_URL` 确认可达 |

## 5.3 白页/EOF/503 修复

```
❌ 不等于重新 publish
✅ 必须先查：process output、listener、HTML 内容
```

# 第六部分 · 防止无限循环

## 6.1 铁律

```
同一条命令失败 3 次后 → 禁止再重试
→ 必须换方案（换工具/简化依赖/改纯HTML）
→ 或告知用户
```

**典型场景：** `npm install` 超时 → 改纯 HTML/CSS/JS 重写，不要无限重试。

# 第七部分 · 审查清单（交付前必做）

## 7.1 技术层

| # | 检查 | 工具 |
|---|---|---|
| 1 | **内链无死链** | 遍历 href 检查文件存在 |
| 2 | **CSS 版本号统一** | 所有页一致（防缓存混乱） |
| 3 | **无 emoji 当 icon** | grep |
| 4 | **有真实图片** | 检查 img 标签 |
| 5 | **响应式** | 检查 viewport meta |
| 6 | **SEO meta** | og/twitter/description |

## 7.2 内容层

| # | 检查 |
|---|---|
| 1 | **章节序号连续**（一二三四…不缺号/不重复） |
| 2 | **无内容重复** |
| 3 | **无空章节**（检测要算表格/图片，不能只看文字） |
| 4 | **信息时效标注**（会过时的加"最后核实日期"） |

## 7.3 发布前验证

```bash
ss -ltnp                              # listener 存在
curl localhost:$PORT                  # 返回 HTML
# publish
curl $PUBLIC_URL                      # 公开可达
```

# 第八部分 · 内容规划（不是先写代码）

## 8.1 顺序

```
内容规划 → 设计 → 编码 → 审计 → 发布
```

**⚠️ 先规划「写什么内容」，再动代码。**
（否则做出"空洞的占位符网站"）

## 8.2 内容要点

| # | 要点 |
|---|---|
| 1 | 标题/正文/CTA **先写出来** |
| 2 | 每段有明确信息（不是"即将上线"） |
| 3 | 真实数据/来源 |

# 第九部分 · 常见坑（真实踩过）

| # | 坑 | 防御 |
|---|---|---|
| **1** | CSS 版本号混乱（10种） | 统一一个版本号 |
| **2** | emoji 当 icon | 换 SVG |
| **3** | 首页无图片 | 加真实图 |
| **4** | 章节序号缺号 | 检查连续性 |
| **5** | 内容重复 | 扫描重复段落 |
| **6** | 检测脚本只看纯文字 | 要算表格/图片 |
| **7** | 悬浮球 bug（拖拽带动其他元素） | fixed 独立 z-index |
| **8** | 改完不推仓库 | 做完就推送 |
