# 踩坑记录（防重复犯错）

> 规则第 0 条要求：「发现错误 → 改机制 → 写进踩坑记录」
> **我之前只有 `知识库/D1_网站/踩坑记录.md`，没有「全局踩坑记录」→ 这就是机制漏洞。**
> 建立：2026-10-04

---

## 使用方法

**每次犯错 → 立刻记入 → 标明触发条件 → 下次先查这里。**

**开工前：扫一遍本文件，看有没有同类坑。**

---

## 🔴 坑 1：有规则但不执行（2026-10-04）

| 项 | 内容 |
|---|---|
| **现象** | 规则第0条要求"每次能力提升留节点"，但10-04一整天0个节点 |
| **用户的话** | 「你的规则到底有没有在执行？已经好几次了」 |
| **归类** | **机制缺**（没有强制检查点） |
| **触发条件** | 任务密集时，只顾往前冲，跳过"记录" |
| **修复** | ① 建本文件 ② 每完成一段工作 → 强制问"要记吗" ③ 开工自检加这项 |

---

## 🔴 坑 2：自称专业但没验证（2026-10-04）

| 项 | 内容 |
|---|---|
| **现象** | 说"顶级方案"，实际业余（提示词不如豆包） |
| **用户的话** | 「你认为最顶尖的提示词是这样的？这真是最顶尖？」 |
| **归类** | **机制缺**（没有自检标准） |
| **触发条件** | 写完方案就下结论，没对照行业标准 |
| **修复** | `rules/专业级自检.md`（L0-L4分级，达标才说） |

---

## 🔴 坑 3：急着下结论，漏看材料（2026-10-04）

| 项 | 内容 |
|---|---|
| **现象** | 用户给8张图让"学习"，我漏看内容就下结论 |
| **用户的话** | 「你有没有好好解析？我让你思考，不是下结论」 |
| **归类** | **机制缺**（没"先完整解析再判断") |
| **触发条件** | 收到材料急着推进 |
| **修复** | 收到材料 → 先**完整解析** → 再**思考** → 最后**才判断** |

---

## 🔴 坑 4：急着推进，跳步（2026-10-04）

| 项 | 内容 |
|---|---|
| **现象** | 提示词没调好就催"开做第1集" |
| **用户的话** | 「不确定就开做 = 返工」 |
| **归类** | **机制缺** |
| **修复** | 开工前自检（技能+知识+思维达标） |
