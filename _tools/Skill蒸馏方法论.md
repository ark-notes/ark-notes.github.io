## 二、仓颉的 RIA-TV++（最完整的方法论）★核心参考

### 根本洞察

> **「现有读书方法论都是为人类读者蒸馏，不是为 agent 执行者蒸馏。」**

| 维度 | 给人看 | **给 agent 用（我们该学）** |
|---|---|---|
| 关键字段 | 故事 / 金句 / 情感钩子 | **trigger / 可执行步骤 / 判停标准** |
| 失败模式 | 读完就忘 | **trigger 不准 → 永不调用或乱调用** |
| 成功标准 | 读者"有收获" | **真实问题被解决** |

### 五阶段流水线

```
阶段 0：整书理解（Adler 四步）
    ↓ BOOK_OVERVIEW.md
阶段 1：5 个 agent 并行提取
    ↓ 候选方法论单元池
阶段 1.5：三重验证筛选
    ↓ verified / reference / needs_review / rejected
阶段 1.6：晋级门（判断是否独立成 Skill）
    ↓
阶段 2：RIA++ 构造能力卡
    ↓ R / I / A1 / A2 / E / B
阶段 3：Zettelkasten 链接（知识网络）
    ↓
阶段 4：压力测试（回炉淘汰）
    ↓
阶段 5：编译与交付
```

### ⭐ 三重验证（最该学的部分）

**每个候选必须通过三关：**

| 验证 | 问题 | 检查什么 |
|---|---|---|
| **V1 来源充分性** | 有可定位的原文支持吗？ | 章节/页码/时间戳；不能只有书名 |
| **V2 可执行性** | 换一组合法输入，能完成任务吗？ | 步骤、分支、判停标准完整 |
| **V3 任务增益** | 固化后能带来什么具体帮助？ | 减少遗漏 / 统一口径 / 改善决策 |

**判定去向：**

| 结果 | 条件 | 处理 |
|---|---|---|
| `verified` | 三关全过 | 进入能力池 |
| `reference` | 有来源但不能独立执行 | 记为参考资料 |
| `needs_review` | 关键条件缺失 | **不许静默消失，必须列出缺口** |
| `rejected` | 无依据 / 被覆盖 | 记录理由 |

### ⭐ RIA++ 六段（每张能力卡的结构）

| 段 | 内容 | 要求 |
|---|---|---|
| **R** Reading 原文 | 直接引用 | ≤150 字 + 出处（章节/时间戳） |
| **I** Interpretation 自述 | **用自己的话重写** | 5-15 行；没读过原文的人能懂 |
| **A1** Application 案例 | 书中案例或明确标记的演练 | 输入→执行→输出；不许冒充真实结果 |
| **A2** Future Trigger ★ | **什么情况下调用它** | ⭐ **最关键 —— 决定是否被用起来** |
| **E** Execution | 可执行步骤 | |
| **B** Boundary | 边界 / 不适用范围 | 诚实说明做不到什么 |

**A2 为什么最关键：**

> 好的 A2：「用户在纠结一个决策、列举正面理由却理不出头绪时；或在问"怎么做 X 才能成功"时；**不适用于纯信息查询类问题**。」
> 坏的 A2：「用户需要思考时。」← 太宽泛，会误激活

### 不变量（不能违反）

1. **原子性** —— 一个能力只做一个单元
2. **可追溯** —— 每个能力有原文引用
3. **可验证** —— 通过三重验证 + 压力测试
4. **可进化** —— 附带评测用例
5. **用户参与** —— 关键节点让用户确认
6. **可交付** —— 终点是"能被调用"

## 三、女娲（nuwa）的方法（蒸馏"人"）

### 核心理念

> **「女娲不是复制人，是提炼思维框架。」**
> **「捕捉的是 HOW they think，不是 WHAT they said。」**

### 一个好的人物 Skill 包含

| 要素 | 说明 |
|---|---|
| **心智模型** | 他用什么**镜片**看世界 |
| **决策启发式** | 他用什么**直觉规则**做判断 |
| **表达 DNA** | 他怎么说话 |
| **反模式** | 他**绝对不会**做什么 |
| **诚实边界** | 这个 Skill **做不到**什么 |

**关键：不要「角色扮演」，要「装载框架」。**

> 例如：给 AI 一个「假装你是芒格」的人设，效果**不如**装载芒格的真实思维框架。
> **人设是装饰，框架才是机制。**

## 四、autoharness 的方法（自进化）

> **「从真实会话中学习 skill，合并同场景的、淘汰不再用的，保持干净。」**

**四个动作：**
| 动作 | 说明 |
|---|---|
| **学（learn）** | 从真实使用中提取 |
| **合并（merge）** | 同类合并，不堆重复 |
| **更新（update）** | 边用边改 |
| **淘汰（prune）** | 没人用的删掉 |

**效果：同一模型，不同 harness，CORE-Bench 42% → 78%**

## 五、应用到 MasterD 的**通用能力**（不限于网站项目）

> ⚠️ **重要修正（用户 2026-10-03 指出）**：
> 「网站只是目前我让你帮我做的一件事，这件事做得差不多了，
>   我可能会让你做其他事，或者咨询你问题。
>   你是我的战略合作伙伴。」
>
> **所以：这套方法论不是"深挖逐字稿专用"，是"任何知识提炼"通用。**

### 适用范围（远远大于网站）

| 场景 | 同样适用 |
|---|---|
| **用户给的长文档** | PDF/报告/白皮书 → 提炼可执行结论 |
| **行业调研** | 多个来源 → 交叉验证 → 结构化输出 |
| **咨询问题** | 快速理解领域 → 给专业判断 |
| **会议/课程记录** | 逐字稿 → 可执行方法论 |
| **竞争对手分析** | 多源信息 → 交叉验证 → 差异化结论 |
| **新领域学习** | 快速建立认知框架 |

### 核心能力（不随项目变）

```
① 提取 —— 从大量信息里捞出真正有价值的
② 验证 —— 交叉核对，标来源，不确定就说不确定
③ 结构化 —— 变成别人能懂、能用的形式
④ 自进化 —— 边做边学，越做越强
```

**这四项，做网站要用，做咨询要用，做任何事都要用。**

## 五之二、应用到当前的深挖流程（现阶段）

### 对照：我现在 vs 业界最佳

| 环节 | 我现在 | 业界最佳 | 差距 |
|---|---|---|---|
| **素材理解** | 直接读 | **阶段 0：先出整书概览** | 🔴 缺 |
| **提取** | 逐支读 | **多路并行提取** | 🟡 慢 |
| **筛选** | 凭感觉 | **⭐ 三重验证** | 🔴 **最缺** |
| **结构** | 【可以直接讲】+【出处】 | **RIA++ 六段** | 🟡 缺 A2/E/B |
| **可调用性** | 人看的话术 | **agent 可调用** | 🔴 缺 |
| **进化** | 无 | **学习/合并/更新/淘汰** | 🔴 缺 |

### 🎯 我的改进（立刻采用）

#### ① 深挖加「三重验证」

**每提炼一条，过三关：**

```
V1 来源充分性：有明确的课次/时间戳吗？
V2 可执行性：换个人照着能讲出来吗？
V3 任务增益：这条能帮用户解决什么问题？
```

**没过关的 → 标 `needs_review`，不许静默丢掉。**

#### ② 每条落点加两段

| 新增 | 内容 |
|---|---|
| **A2 什么时候用** | ⭐ **什么场景下该讲这条话术** |
| **B 边界** | 什么情况下**不能用**这条 |

**为什么加 B —— 因为你上次说过：「不好的消息我得知道，为什么不影响」。边界就是防打脸。**

#### ③ 学习 autoharness 的「自进化」

**我的对话记录 + 踩坑记录 = 学习材料：**
```
做任务 → 记录结果 → 复盘 → 更新规则 → 下次更好
```

#### ④ 学习女娲的「HOW not WHAT」

**深挖讲师内容时：**
- ❌ 只记「他说了什么」（WHAT）
- ✅ **记「他为什么这么说、遇到质疑怎么接」（HOW）**

---

## 六、我的自我要求（写进规则）

1. **每提炼一条，必过三重验证**
2. **每条必须标「什么时候用」和「什么时候不能用」**
3. **查不到依据的，标 `needs_review`，不静默丢掉**
4. **原始引用不许改写**（R 段直接引用）
5. **自己的话重写**（I 段，不许照搬）
6. **定期复盘，更新规则**（自进化）
